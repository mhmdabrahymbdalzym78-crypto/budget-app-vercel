# تطبيق الميزانية والدروس — نسخة GitHub وVercel

هذا المشروع يحتفظ بواجهة HTML المرفقة كما هي تقريبًا (من دون إعادة تصميم)، ويضيف تسجيل دخول، مزامنة سحابية لكل حساب، تنبيهات داخل الموقع، بريدًا عربيًا منسقًا، وإشعارات Web Push اختيارية، مع لوحة متحكم محمية وسجل تدقيق.

## مهم قبل النشر

- الملف المرفق الأصلي كان مقطوعًا في منتصف JavaScript؛ لذلك أُعيد توصيل الوظائف الأساسية هنا بدل ترك صفحة غير مكتملة.
- لا يوجد رمز متحكم ثابت داخل ملفات الواجهة. لا تضع أسرارًا في GitHub. الرمز الذي ظهر في المحادثة يجب تغييره وعدم إعادة استخدامه.
- حساب المتحكم يستطيع الاطلاع على جميع البيانات المالية؛ تظهر للمستخدمين رسالة إفصاح قبل التسجيل، ويُسجّل الخادم كل طلب مصرح به لعرض السجلات. استخدم فقط مع سياسة خصوصية وإشعار مناسبين.
- البريد وWeb Push اختياريان بعد إعداد Resend وVAPID، ويجب أن يوافق كل مستخدم على قناة البريد ويمنح إذن المتصفح للإشعارات. لا يتضمن البريد تفاصيل مالية.
- معلومات Supabase الظاهرة للمتصفح هي عنوان المشروع و`anon key` فقط؛ المفتاح السري `service role` للخادم في Vercel وحده.

## الملفات

- `index.html` — الواجهة العربية الأصلية مع شاشة تسجيل الدخول ولوحة المتحكم.
- `app.js` — المصادقة، قراءة البيانات وحفظها، إدارة السجلات، والتقارير والتنبيهات.
- `api/config.js` — يمرّر قيم الواجهة العامة المطلوبة فقط.
- `api/admin-data.js` — يتحقق من جلسة المستخدم ودور المتحكم على الخادم، ثم يسجل عملية الاطلاع قبل إعادة البيانات.
- `api/notify.js` — يصدر بريدًا عربيًا منسقًا عبر Resend وإشعارات Web Push بعد موافقة المستخدم.
- `sw.js` — يستقبل إشعارات المتصفح حتى عند إغلاق تبويب الموقع.
- `supabase/schema.sql` — جداول البيانات والعزل وسجل التدقيق واشتراكات الإشعارات.
- `supabase/promote-admin.sql` — ترقية حساب المتحكم الذي حددته بعد تسجيله وتأكيد بريده.
- `vercel.json` — إعدادات نشر بسيطة متوافقة مع Vercel.

## 1) إنشاء قاعدة البيانات والمصادقة

1. أنشئ مشروعًا في Supabase.
2. افتح **SQL Editor** ونفّذ محتوى `supabase/schema.sql` كاملًا.
3. من **Authentication → Providers** فعّل Email/Password. فعّل تأكيد البريد إذا كان مناسبًا لمشروعك، واضبط عناوين إعادة التوجيه إلى نطاق Vercel الذي ستنشر عليه.
4. أنشئ حسابك الشخصي من شاشة الموقع بعد النشر، ثم أكّد البريد وسجّل الدخول مرة واحدة.
5. بعد تأكيد البريد وإنشاء الحساب، شغّل ملف `supabase/promote-admin.sql` في Supabase SQL Editor. يرقّي البريد الذي زودتني به إلى متحكم. إذا كان البريد لم يُسجل بعد، فلن يضيف الاستعلام شيئًا؛ أنشئ الحساب أولًا ثم أعد تشغيله:

```sql
insert into public.app_admins (user_id)
select id from auth.users where lower(email) = lower('amhmdabrahymbdalzym@gmail.com')
on conflict (user_id) do nothing;
```

لا تضف أي مستخدم لا ينبغي أن تكون له صلاحية الاطلاع الكامل.

## 2) رفع الملفات يدويًا إلى GitHub

1. أنشئ مستودعًا جديدًا على GitHub.
2. ارفع **محتويات** مجلد المشروع كما هي إلى جذر المستودع، بما فيها مجلدا `api` و`supabase`.
3. لا ترفع ملف `.env` أو مفتاح `service_role`. ملف `.gitignore` مرفق للحماية.

## 3) ربط GitHub بـ Vercel

1. في Vercel اختر **Add New → Project** ثم استورد مستودع GitHub.
2. اترك **Framework Preset** على Other، وRoot Directory على جذر المستودع. لا تحتاج إلى أمر Build لموقع HTML ثابت؛ يمكن تركه فارغًا. أمر التثبيت الافتراضي `npm install`.
3. في **Project Settings → Environment Variables** أضف القيم التالية لبيئات Preview وProduction (وأضف Development إن رغبت):

| الاسم | القيمة | أين تجدها |
|---|---|---|
| `SUPABASE_URL` | عنوان مشروع Supabase | Supabase → Project Settings → API |
| `SUPABASE_ANON_KEY` | المفتاح العام anon/publishable | Supabase → Project Settings → API |
| `SUPABASE_SERVICE_ROLE_KEY` | المفتاح السري للخادم فقط | Supabase → Project Settings → API / API Keys |
| `RESEND_API_KEY` | مفتاح إرسال البريد | Resend → API Keys |
| `EMAIL_FROM` | المرسل الموثّق، مثل `محفظتي <alerts@your-domain.com>` | نطاق موثّق في Resend |
| `APP_URL` | رابط الموقع المنشور على Vercel، يبدأ بـ `https://` | نطاق Vercel |
| `VAPID_PUBLIC_KEY` | مفتاح Web Push العام | يُولّد محليًا بأمر web-push الموضح أدناه |
| `VAPID_PRIVATE_KEY` | مفتاح Web Push السري | يُولّد محليًا؛ يحفظ في Vercel فقط |
| `VAPID_SUBJECT` | وسيلة تواصل، مثل `mailto:amhmdabrahymbdalzym@gmail.com` | بريد المشغّل |

**لا تضع المفاتيح السرية في `index.html` أو `app.js` أو مستودع GitHub.** ثم أعد النشر بعد إضافة المتغيرات.

### تفعيل البريد والتنبيهات

1. أنشئ حساب Resend، وثبّت نطاق إرسال تملكه وتحقق منه، ثم أنشئ API key. لا تستخدم عنوانًا من نطاق Gmail كمرسل؛ `EMAIL_FROM` يجب أن يكون من النطاق الذي تحقق منه Resend.
2. أنشئ مفاتيح VAPID محليًا باستخدام: `npx web-push generate-vapid-keys`. انسخ المفتاحين إلى متغيري Vercel المناسبين، ولا تنشر المفتاح الخاص.
3. أضف بقية القيم أعلاه في Vercel ثم أعد النشر.
4. بعد تسجيل الدخول، افتح جرس التنبيهات، فعّل خيار البريد أو اضغط تفعيل إشعارات المتصفح. إذن المتصفح لا يظهر إلا بعد ضغط المستخدم. قوالب تأكيد البريد/استعادة كلمة المرور الافتراضية يمكن تعديلها أيضًا من **Supabase → Authentication → Email Templates**.
5. عند تجاوز الميزانية/الاقتراب من الحدود أو استحقاق تذكير، يرسل الخادم رسالة عربية منسقة إلى بريد صاحب الحساب نفسه (إذا وافق)، وإشعار Push إلى أجهزته المشتركة. تُزال الاشتراكات المنتهية ويُمنع التكرار حسب نوع التنبيه واليوم، مع حد أقصى 8 رسائل بريد لكل مستخدم خلال 24 ساعة.

إذا لم تُهيّئ Resend أو مفاتيح VAPID فلن يُرسل بريد أو Push، لكن تبقى التنبيهات داخل الموقع عاملة.

## 4) التحقق بعد النشر

- افتح رابط Vercel، أنشئ حسابًا تجريبيًا وسجّل الدخول.
- أضف مصروفًا، انتظر ظهور «تم الحفظ سحابيًا»، ثم سجّل الخروج وادخل مجددًا أو افتح الموقع في متصفح آخر. يجب أن تجد البيانات نفسها.
- جرّب إضافة تنبيه بموعد اليوم وتحقق من ظهور شارة الإشعارات. التنبيه مشتق من الميزانية والحدود والتذكيرات.
- تحقق أن حساب مستخدم عادي لا يرى زر المتحكم ولا يستطيع طلب `/api/admin-data`، وأن حساب المتحكم المخوّل يرى البيانات وأن سجل `admin_access_logs` يسجل الاطلاع.
- لا تحذف قاعدة البيانات أو مشروع Supabase بعد رفع الملفات؛ GitHub وVercel يستضيفان الكود ولا يحلان محل قاعدة البيانات.

## التطوير المحلي

يتطلب تشغيل وظائف API المحلية Vercel CLI مع قيم البيئة نفسها. انسخ `.env.example` إلى `.env.local` وأدخل القيم محليًا (لا ترفع `.env.local` إلى GitHub)، ثم شغّل `npx vercel dev`. أو استخدم Preview Deployment بعد إدخال متغيرات Vercel.

## ملاحظات عن الحفظ والإشعارات

- `localStorage` وحده يحفظ على المتصفح الحالي فقط؛ هذه النسخة تجعل Supabase مصدر البيانات الدائم، مع عزل كل سجل بـ `user_id` وسياسات RLS. قبل الانتقال من رابط الموقع القديم، صدّر ملف JSON من الموقع القديم واحتفظ به؛ بعد التسجيل في النسخة الجديدة استخدم «استرجاع نسخة احتياطية» لاستيراده. بيانات `localStorage` لا تنتقل تلقائيًا بين نطاقين مختلفين.
- تظهر حالة المزامنة في الترويسة. عند فشل الاتصال لا تعرض الواجهة نجاحًا كاذبًا؛ صدّر JSON من الإعدادات كنسخة احتياطية وانتظر حالة نجاح الحفظ.
- التنبيهات داخل التطبيق تُحسب عند التحميل وبعد تغييرات البيانات. يُطلب إرسال البريد/Push عند فتح التطبيق أو حفظ تعديل يحقق شرط تنبيه؛ وبعد ذلك يمكن لـ Web Push الظهور حتى إن أُغلق التبويب. يتطلب البريد نطاقًا موثقًا في Resend، وتتطلب Push إذن المستخدم ومفاتيح VAPID ومتصفحًا داعمًا؛ على iPhone/iPad يتطلب Web Push عادةً إضافة الموقع إلى الشاشة الرئيسية وإصدار iOS/iPadOS مدعومًا.
